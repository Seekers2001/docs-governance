# 共享日志解析与审计结果接口：架构优化验证

日期：2026-09-05。

## 本轮范围

阿磊确认的架构优化：日志审计和归档索引共享格式解析；审计先生成结构化结果，再输出文字或 JSON。项目已有代码审查和测试工具继续执行，治理只引用版本、范围、结论及证据位置，并区分人工文档与运行结果的维护方式。

同时纳入已确认的风险分级调整：行数或覆盖率只作检查线索，按实际影响判风险；普通验证缺口移出 P0 区，日志聚焦有意义的结果。

## 验收证据

| 要求 | 实际验证 |
|---|---|
| 日志格式只维护一套，旧归档行为保留 | `scripts/logformat.py` 由两个 CLI 引用；旧日志与审计测试继续通过 |
| 多行正文与代码块不因提取解析器而丢失 | 201 条中文多行事件经过真实归档后原文仍在，基于原始 Git 提交的审计通过 |
| 同一发现可供人和工具读取 | 同一断链的文字与 JSON 结论、退出码和证据一致；Shell 入口可从目标项目目录返回 JSON |
| 无法验证不伪装成通过 | 无 Git 历史返回 `unverified`，孤儿提示返回 `warning`；保持渐进采用的退出码 0 |
| 文档问题与检查执行失败分开 | 断链或日志格式错误为 1；无效根目录、无效基准和读取失败为 2，JSON 仍可解析 |
| 证据携带版本和范围 | 测试覆盖实际提交、干净与有未提交改动的工作区、日志基线以及具体日志行号 |

默认 runner 共 37 个测试通过；原有测试继续覆盖双 Agent 写回保护、机器契约模板和独立目录审计。标准提交前入口：

```bash
source .venv/bin/activate
DOCS_GOVERNANCE_BASE_REF=origin/main bash scripts/verify.sh
```

## 使用边界

- 运行脚本仍只用 Python 标准库；没有新增后台服务、任务调度器或代码审查 Skill。
- JSON 结果是本次观测，不冻结文件系统、不缓存通过状态；未提交内容不能只用 HEAD 标识，相关变更后必须重跑。
- 接口支持检查项、状态、来源与证据复用；未实现外部工具的自动导入或健康状态自动刷新。
- 真实业务项目对证据接入的试点、Claude Code 原生 slash command 与 Stop hook 行为验收仍保留原缺口。
