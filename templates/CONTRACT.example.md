# CONTRACT.md —— 接口契约入口与协作约定

> 字段、类型、枚举、路径和错误响应的唯一来源是下表的机器契约；本文不另抄字段表。
> 契约拥有者是指定的人或当前主会话；消费方和提供方只读。变更请求发给拥有者，不直接修改契约。

## 权威来源

| 项 | 本项目填写 |
|---|---|
| 机器契约 | `contracts/openapi.json`（采用时填写真实路径） |
| 格式 | OpenAPI 3.1；已有其他机器契约时沿用，不复制第二份 |
| 版本证据 | 填写提交 SHA 或文件内容 hash |
| 拥有者 | 填写指定的人或主会话 |

空项目需要 HTTP 契约时，将插件 `templates/openapi.example.json` 复制到选定位置，按已确认需求修改；里面的订单只是示例。已有机器契约时只登记入口，不再复制模板。

## 同一来源的执行入口

| 证据层 | 项目命令与输出位置 |
|---|---|
| 契约格式校验 | 填写针对上述文件的 OpenAPI/schema 校验命令 |
| 消费方类型和 mock | 填写由同一契约生成或校验的命令及产物路径 |
| 提供方验证 | 填写针对真实序列化响应的校验命令 |
| 最小跨端联调 | 填写真实业务路径、命令和 TEST-ID；未运行时登记缺口 |

采用时填写可执行命令，不能把表格占位符写成已验证。Python 示例可用 `openapi_spec_validator.validate` 校验格式，再用 `jsonschema` 引用同一 OpenAPI 文档的响应 schema；本插件的可执行参考在 `tests/test_contract_template.py`。

## 变更须知

先由拥有者更新机器契约 → 更新版本证据 → 重新生成或校验消费方资产 → 验证提供方序列化结果 → 跑最小联调。

破坏性变化同时记录兼容期、消费者迁移顺序、回滚条件和不可逆部分；缺少这些信息时不进入实现。契约变更按活文档 Skill 的标准事件格式追加 LOG，并将验证证据登记到 TESTS，本文仅引用。
